# Восстановление всего в новом окружении

**Короткий ответ:** всё живёт в GitHub. Секреты и рабочие данные — в зашифрованном
виде, там же. Единственное, что вы храните вне репозитория, — **мастер-пароль**.

---

## Что где хранится

| Что | Где | Как защищено |
|---|---|---|
| Код, исследования, статус, задачи | GitHub, открытым текстом | публичный репозиторий |
| **Токены, пароли, API-ключи** | `secrets/vault.enc` в GitHub | AES-256-CBC + PBKDF2 240k |
| **Рабочие данные (заказы, P&L)** | `secrets/data-backup.tar.gz.enc` | тот же шифр, тот же пароль |
| Мастер-пароль | **только у вас в голове / менеджере паролей** | нигде не записан |

Открытым текстом `data/ledger.json` в git **не попадает** — он в `.gitignore`.
В репозиторий уходит только его зашифрованная копия.

---

## Первичная настройка (один раз)

```bash
cd aliexpress
export VAULT_PASSPHRASE='придумайте-длинный-пароль'

./scripts/vault.sh init     # создать хранилище секретов
./scripts/vault.sh edit     # вписать GITHUB_TOKEN и прочее
./scripts/backup.sh save    # зашифровать и запушить рабочие данные
```

⚠️ **Пароль запишите в менеджер паролей прямо сейчас.** Без него данные
не восстановить — это не фигура речи, восстановления не существует.

---

## Восстановление в новом окружении

Три команды. Работает на любой машине, в любой песочнице.

```bash
git clone https://github.com/JoTalbot/aliexpress.git && cd aliexpress
export VAULT_PASSPHRASE='ваш-пароль'

./scripts/backup.sh restore      # вернуть заказы и P&L
eval "$(./scripts/vault.sh export)"   # загрузить секреты в окружение
./scripts/bootstrap.sh           # настроить git, проверить инструменты и тесты
```

Проверено на практике: клон в чистую директорию → восстановление →
`order_ledger.py pnl` показывает те же 6 заказов и итог +32.40.

## Регулярная работа

| Когда | Команда |
|---|---|
| Каждые 10–15 минут работы | `./scripts/save.sh "описание"` — код и документы |
| После изменения заказов | `./scripts/backup.sh save` — зашифрованные данные |
| Проверить, всё ли сохранено | `./scripts/backup.sh diff` |
| Сменить токен/пароль сервиса | `./scripts/vault.sh edit` затем `save.sh` |

**Важно:** `save.sh` коммитит код, но **не** трогает `data/` — он в `.gitignore`.
Для данных нужен отдельный `backup.sh save`. Это сделано намеренно:
данные шифруются, код — нет.

## Альтернативы, если не хотите хранить в GitHub

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Текущий: шифртекст в GitHub** | ничего лишнего не нужно, история версий, работает везде | шифртекст публичен — стойкость упирается в пароль |
| Приватный репозиторий | шифртекст не виден посторонним | нужен второй репозиторий |
| Отдельный gist (приватный) | отделено от основного кода | ещё одно место для синхронизации |
| Облако (Dropbox/Drive) | привычно | ручная синхронизация, нет версий |
| Менеджер паролей (1Password, Bitwarden) | правильное место для секретов | не подходит для данных ledger |

**Рекомендация:** если содержимое vault станет чувствительным (реальные ключи,
платёжные данные) — переведите репозиторий в приватный. Сейчас там только
шаблон, а стойкость AES-256 с длинным паролем достаточна и для публичного.

## Если пароль утерян

Восстановления нет. Порядок действий:

```bash
rm secrets/vault.enc secrets/data-backup.tar.gz.enc
export VAULT_PASSPHRASE='новый-пароль'
./scripts/vault.sh init
```

Все токены перевыпустить заново, данные ledger вводить с нуля.
Именно поэтому пароль — в менеджер паролей, а не «запомню».

## Что проверить перед тем, как закрыть окружение

```bash
git status                    # должно быть чисто
./scripts/backup.sh diff      # «Бэкап актуален»
python3 tests/test_tools.py   # 41 тест OK
```

Если все три зелёные — окружение можно терять без потерь.
