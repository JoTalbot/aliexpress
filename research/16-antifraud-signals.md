# 16 · Сигналы антифрода: как платформа оценивает претензию (T-016)

**Актуально на:** 2026-08-17 · **Задача:** T-016
**Зачем добросовестному покупателю:** понимание модели объясняет, почему **честные**
претензии иногда проигрывают, и как этого избежать. Это не инструкция по обходу —
обход невозможен без подачи ложных сведений, что и есть мошенничество (`SCOPE_AND_ETHICS.md`).

---

## 1. Главное: решает не человек, а модель

Кейсы показывают: споры по дешёвым позициям у покупателей с хорошей историей
закрываются **за минуты**, без участия оператора. Это автоматическое решение.
Значит, оценивается не «справедливость», а **набор сигналов**.

Отраслевая рамка называется **динамическое доверие** (dynamic trust):
доверенным — мгновенный возврат, рискованным — дополнительная верификация,
пограничным — ручной разбор.

---

## 2. Сигналы, которые считываются

### Уровень аккаунта

| Сигнал | Влияние |
|---|---|
| Доля заказов со спорами | ключевой; высокая → отказы даже по честным заявкам |
| Возраст аккаунта и объём покупок | длинная нормальная история = кредит доверия |
| Статус покупателя | высокий статус коррелирует с автоодобрением |
| Доля INR-претензий («не получил») | самая контролируемая категория |
| Соотношение «возвраты / покупки» | при перекосе — переход в группу риска |
| Связывание идентичностей | устройство, платёжные данные, адреса — мультиаккаунт вычисляется |

### Уровень претензии

| Сигнал | Влияние |
|---|---|
| Скорость подачи | претензии в первые ~7 дней статистически чаще недобросовестные |
| Категория | INR проверяется строже прочих |
| Наличие доказательств в первой заявке | ускоряет одобрение |
| Согласованность описания и доказательств | расхождение = красный флаг |
| Смена причины по ходу спора | подозрительно, ослабляет позицию |
| Сумма относительно стоимости логистики | дешевле вернуть деньги, чем принять товар — влияет на исход |

### Уровень доказательств

| Сигнал | Влияние |
|---|---|
| Непрерывность видео | склейки обесценивают запись |
| Метаданные файлов | оригинал против пересохранённого в редакторе |
| Признаки генерации/редактирования | детекторы shallowfake внедрены отраслью с 2025 |
| Повторное использование изображений | реверс-поиск по базе прошлых претензий |
| Соответствие фото заявленной проблеме | «повреждён» + фото целого товара = отказ |

### Уровень продавца и заказа

История продавца, доля споров по конкретному листингу, данные логистики платформы
(для Choice — собственный трекинг, который проверяется автоматически).

## 3. Почему честные претензии иногда проигрывают

| Причина | Что происходит |
|---|---|
| Профиль испорчен прошлыми спорами | модель понижает доверие ко всем последующим заявкам |
| Претензия подана слишком быстро | попадает в статистически подозрительную группу |
| Фото «улучшены» в редакторе | метаданные изменены → похоже на фабрикацию |
| Выбрана неверная категория («подделка» без атрибуции бренда) | автоматический отказ по формальному признаку |
| Доказательства досланы позже | первое решение принято без них |
| Много мелких споров подряд | триггер поведенческого паттерна |

---

## 4. Что делать добросовестному покупателю

1. **Беречь профиль.** Не спорить по позициям в пару долларов. Это буквально
   расходует ресурс, который понадобится на дорогом заказе.
2. **Не торопиться без причины.** Если товар в пути и срок не вышел — не подавать INR.
3. **Использовать точную категорию.** «Не соответствует описанию» вместо «подделка»,
   если нет явной атрибуции бренда.
4. **Оригиналы файлов.** Не редактировать, не пересохранять, не кропать.
   Снимать сразу так, чтобы правка не потребовалась.
5. **Всё в первую заявку.** Доказательства, приложенные позже, могут не успеть.
6. **Одна версия событий.** Не менять причину и формулировки по ходу спора.
7. **Быть предсказуемым покупателем.** Нормальная история покупок и подтверждений
   работает на вас в моделях доверия.

## 5. Для дропшиппера отдельно

Риск системный: потеря аккаунта = остановка бизнеса. При этом объём заказов
естественным образом даёт больше проблемных случаев.

- считать **долю** споров, а не абсолютное число (`order_ledger.py pnl` предупреждает при >20%);
- отбраковывать проблемные позиции и поставщиков вместо наращивания споров;
- диверсифицировать поставщиков — не только против исчезновения, но и против
  концентрации претензий по одному листингу;
- держать резервный аккаунт **нельзя** — связывание идентичностей это выявляет,
  и последствия хуже, чем исходная проблема.

## 6. Чего в этом материале нет

Способов «выглядеть доверенным», не будучи им; методов обхода детекции;
рекомендаций по прогреву аккаунтов. Всё это относится к мошенническому сценарию
и исключено по ADR-002. Разбор индустрии как явления — `research/06`.
