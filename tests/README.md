# tests/ — регрессионные тесты

```bash
python3 tests/test_tools.py       # перед каждым push
python3 tests/test_tools.py -v    # подробно
```

Только стандартная библиотека. Работают на временных файлах, боевые данные не трогают.

## Что защищено (67 тестов на 2026-08-17; актуальное число — в прогоне)

| Группа | Что проверяет |
|---|---|
| `TestDeadlines` | Расчёт окон Buyer Protection — **самое критичное** |
| `TestMoney` | P&L, разрыв оборотки, ожидаемые возвраты |
| `TestPersistence` | Сохранение/загрузка, кириллица |
| `TestRiskScore` | Веса скоринга, включая репутацию аккаунта (T-011) |
| `TestRouteCalc` | Сбор ЕС на строку декларации, пошлины UA, регрессия бага наценки |
| `TestRemind` | Детекция просрочек, зависших споров |
| `TestImport` | Парсинг денег/дат, распознавание колонок RU/EN |
| `TestScopeGuard` | Границы проекта, отсутствие секретов в коммитах |

## Правило про бизнес-константы

Значения окон (15 дней, 60 дней BP) захардкожены **намеренно**. Это внешние правила
AliExpress, а не наша конфигурация. Тест, сверяющийся с константой модуля,
тавтологичен — он не поймает случайное изменение правила.

`test_business_constants_unchanged` специально дублирует значения:
меняешь константу — проверь первоисточник, обнови `research/12` и тест осознанно.

## Грабли: `__pycache__`

Если правишь константы через `sed` и размер файла не меняется, Python может взять
устаревший байткод, и тесты покажут ложный результат. Перед прогоном:

```bash
find . -name __pycache__ -type d -exec rm -rf {} +
```

`scripts/bootstrap.sh` делает это автоматически.
